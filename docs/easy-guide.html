쉽게 보는 설명서

내가 만든 할 일 앱은
어떻게 인터넷에 떴을까?

전문 용어 없이, 세 단계로 설명해드릴게요. 코드를 짜서 → 인터넷에 열고 → 데이터를 저장하는 곳까지 연결하면 누구나 접속해서 쓸 수 있는 앱이 완성됩니다.

한눈에 보는 전체 흐름

📦
① 코드 보관
GitHub
→
🌐
② 인터넷에 열기
Vercel
→
🗄️
③ 데이터 저장
Supabase

각 단계, 비유로 설명하면

1
GitHub — 원고를 보관하는 창고

앱을 만드는 데 쓴 코드컴퓨터에게 "이렇게 동작해라"라고 적어둔 글. 앱의 설계도 같은 것를 안전하게 보관하는 창고예요. 나중에 수정하거나 여러 사람이 함께 작업할 때도 여기서 관리해요.

2
Vercel — 창고 원고를 실제 가게로 여는 곳

창고(GitHub)에 있는 코드를 가져다가, 인터넷 주소(URL)로 접속하면 실제로 화면이 뜨도록 배포완성된 프로그램을 사람들이 실제로 쓸 수 있게 인터넷에 올리는 것해주는 서비스예요. 우리 앱의 진짜 "가게 문"이 여기예요.

3
Supabase — 손님들이 남긴 기록을 적어두는 장부

사람들이 앱에서 "할 일"을 추가하면, 그 내용을 어딘가엔 계속 기억해둬야겠죠. Supabase는 그 기록을 잃어버리지 않게 보관해주는 데이터베이스정보를 표(엑셀과 비슷한 형태)로 정리해서 저장해두는 시스템예요.

왜 하나로 합치지 않고 세 개나 썼을까요?

세 회사가 각자 제일 잘하는 일 하나씩만 맡고 있어서예요. 창고 회사는 보관을, 가게 자리를 빌려주는 회사는 손님 응대를, 장부 회사는 기록만 전문으로 하는 것과 비슷해요. 그래서 서로 연동서로 다른 서비스가 정보를 주고받을 수 있도록 연결하는 것만 시켜주면, 각자 잘하는 일에 집중하면서도 하나의 앱처럼 동작하게 만들 수 있어요.

그래서 지금 뭘 할 수 있나요?

1

아래 주소로 접속하면 할 일 목록 화면이 떠요.

2

입력창에 할 일을 적고 "추가"를 누르면 목록에 저장돼요.

3

체크박스를 누르면 완료 표시가 되고, "삭제"를 누르면 지워져요.

4

이 모든 기록은 Supabase 장부에 저장되기 때문에, 나중에 다시 들어와도 그대로 남아있어요.
